# 작업 목록

결정된 작업과 각 항목의 확인 여부다. 한 항목을 끝내면 이 파일의 상태를 고친다. "확인함"은 실제로 돌려 본 것이고, "확인 안 함"은 추측이거나 아직 해 보지 않은 것이다.

### 3. 부분 점수는 실제 피해가 나는 것만

- 공격되거나 실제 피해가 나는 결함만 깎는다. 피해가 입증되지 않는 설정 항목은 감점하지 않는다.
- **대상 후보:** CSP 단독 미설정, HTTP에서의 HSTS·Secure 플래그, 보안 로깅, medium CVE
- 항목별 표를 만들어 사용자에게 확인받은 뒤 바꾼다. `scripts/verify/sim_scores.py`로 점수 변화를 함께 보여준다.
- **제안:** csp, security_headers, cookie_flags, security_logging, session_timeout을 참고로 옮기고 CVE medium·low 감점을 없앤다.
  - 저장된 22개 결과로 계산하면 중앙값 +4.90점, 순위가 바뀌는 앱은 #6, #10, #26, #28, #29다. 확인함.
  - 바뀐 로직으로 실제 재채점은 확인 안 함.
- **상태:** 구현함 (2026-10-30). 원칙은 공격이 성공할 수 있을 때만 깎는다.
  - csp, security_headers, cookie_flags, security_logging, session_timeout을 `reference`로 옮기고 weight 0으로 했다.
  - weak_default_secret, hardcoded_secret도 소스에서만 보이는 설정이라 같은 방식으로 참고로 옮겼다.
  - CVE medium·low 감점을 0으로 했다. 목록에는 남고, 감점이 없으면 통과다.
  - 카테고리 가중치를 다시 더했다. A02 5.5, A04 6, A07 25.5, A09 0.
  - A09처럼 가중 검사가 없는 카테고리는 점수에서 빠지고 화면에도 안 나온다. 가중 검사가 하나도 없으면 원점수는 0이다.
  - 순수 파이썬 테스트는 확인함. 도커가 필요한 정답 대조와 실제 재채점은 확인 안 함.
