# vibe-security-score — Architecture

Booth game: a participant types a prompt → the server runs **Codex CLI** (operator's
ChatGPT login) to generate a **Flask board app** → the grader auto-scores that code →
the UI shows score/grade. Participants never edit code.

## Fixed stack (do not confuse)

| Concern | Tech | Notes |
|---|---|---|
| Grader web / queue / dashboard | **Django** | Operator server. |
| Participant-generated app | **Flask** | The grading *target*, generated by Codex. |
| Participant app execution | **`python:3.11-slim` container** | Non-root, resource-limited, timeout. **Network stays ON.** |

Grader env and participant Flask env are **never shared**: the participant
`requirements.txt` (possibly vulnerable/typosquatted) installs **only inside the
container**, never on the grader host.

## Four parts

1. **Web UI (Django, `grader/`)** — `Submission` model + state machine
   (`queued → generating → scoring → done | failed | rate_limited`), all transitions via
   `submissions/state.py`. Participant flow: editable prefilled prompt → submit → poll
   status + queue position → result (per-item ✔/✘ + 감점 사유 + 부분 점수 + 등급); public
   leaderboard at `/ranking/`. Operator: Django admin (submissions, scores, queue, retry
   failed). Bootstrap UI (vendored, offline). Operator accounts use a custom
   `accounts.Operator` user model with **no email column** (email is a participant-app
   concept, not a grader one).
2. **Codex runner (`codex_runner/`)** — `codex exec` (non-interactive), prompt via
   stdin, harvest `app.py`/`requirements.txt`/`templates/` and write `prompt.md`. ChatGPT
   auth only — `OPENAI_API_KEY`/`CODEX_API_KEY` blanked, no API-key fallback. `codex.model`
   empty ⇒ the account's default model (API-only ids like `gpt-5-codex` are rejected by
   ChatGPT-account auth). Serial use (5h rolling limit); per-run timeout; logs never leak
   to the booth UI. On Windows the npm `.cmd` shim is run via `cmd /c`; real generation
   needs a Linux/macOS/WSL sandbox (`python -m codex_runner.smoke`).
3. **Grading engine (`scoring/`)** — pure-Python (no Django import), standalone-testable.
   - **(A) Static** — hardcoded secrets, `debug=True`, password hashing, raw vs
     parameterized SQL, XSS sinks (source + `templates/`), cookie flags, security headers,
     prompt intent; deps → CVE (OSV CLI or local snapshot) + typosquatting. Optional
     tools (gitleaks/semgrep/osv-scanner/pypi) skip cleanly if absent.
   - **(B) Dynamic** — boot the app in the container, attack with `requests`: functional
     gate (incl. wrong-password rejection, judged by auth state not status code — form
     apps 200-rerender the login form), IDOR (2-account cross access), admin access
     control, stored XSS, SQLi (sqlmap or built-in oracle). IDOR/access-control judged by
     **runtime cross-access only**. Untestable checks are **skipped** (excluded from the
     score), never scored 0. Timeouts throughout; container teardown in `finally`.
4. **Orchestrator (`grader/submissions/orchestrator/`)** — one worker:
   **serial generation** (global lock — shared ChatGPT limit) feeding **bounded-parallel
   scoring** (isolated containers, `scoring_concurrency`). Retry/backoff; rate-limit holds
   are re-queued (not dropped); failed submissions retryable from admin. The worker does a
   one-time orphan sweep at **startup** (safe — nothing in flight), which replaces a
   separate janitor process.

## Sandbox (`sandbox/`)

`python:3.11-slim`, non-root (uid 10001), memory/cpu/pids limits, network ON. A
`sitecustomize.py` on `PYTHONPATH` forces any Flask app to bind `0.0.0.0:5000` with the
reloader off — generated apps commonly use `app.run(debug=True)` (binds 127.0.0.1,
unreachable through Docker's port map).

## Scoring

- Each check 0–100, combined by config weights (category avg → weighted across
  categories; **skipped checks excluded**).
- All weights/thresholds/penalties/grade-cuts live in one file:
  [`config/scoring.yaml`](../config/scoring.yaml) — nothing hardcoded in logic.
- Functional/boot gate failure caps the final score. Grades from `grades` thresholds
  (60 통과 / 80 우수 / 95 최고). Security items are not disclosed pre-grading — only as
  penalty reasons on the result screen.

## Repo layout

```
config/scoring.yaml         # THE single scoring config
config/default_prompt.txt   # prefilled participant prompt
scoring/                    # grading engine (pure python)
codex_runner/               # Codex exec wrapper (+ smoke.py dev test)
grader/                     # Django project; under submissions/orchestrator/; accounts/ (Operator model)
sandbox/                    # Dockerfile + entrypoint.sh + sitecustomize.py
samples/vulnerable_board/   # deliberately vulnerable Flask app — test fixture
data/                       # local fixed snapshots (popular packages, OSV)
deploy/                     # prod: gunicorn + systemd + nginx (see deploy/README.md)
pyproject.toml / uv.lock    # deps (uv)
```

## Environments

prod = Ubuntu. Deps managed with **uv**. Verify by grading
`samples/vulnerable_board/` (planted secret incl. `config['SECRET_KEY']=`, IDOR, stored
XSS, admin access, SQLi must lose points). Production deploy: [deploy/README.md](../deploy/README.md).
